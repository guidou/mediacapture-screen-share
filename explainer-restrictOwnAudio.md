## Introduction
The [Screen Capture](https://w3c.github.io/mediacapture-screen-share/) API allows users to share their screen, typically in videoconferencing scenarios that involve [WebRTC](https://w3c.github.io/webrtc-pc/) to send the screen capture together with other audio and video to remote users. The screen capture may consist of a browser tab, an application window or the full screen. The captured content (tab, window or screen) is often referred to as a captured surface.

When the captured surface is a window or screen, the user can choose to share system audio as part of the captured content. System audio will contain audio played by all applications, so an user can share audio from applications other than the browser. 

If a captured surface with system audio is shared in videoconferencing the captured (and shared) system audio will also contain the audio generated by the video conference. If a participant in the meeting speaks, their voice will be part of the captured and shared audio, so the participant will end up hearing their own voice.

[restrictOwnAudio](https://w3c.github.io/mediacapture-screen-share/#dom-mediatracksupportedconstraints-restrictownaudio) is a new member of the [extended MediaTrackSupportedConstraints dictionary](https://w3c.github.io/mediacapture-screen-share/#extensions-to-mediatracksupportedconstraints) that will solve this issue. Setting it to true will remove any audio originating from the page that does Screen Capture from the system audio. In the scenario above, the voice from other participants will no longer be captured and shared, thus preventing echos.

The specification for [restrictOwnAudio](https://w3c.github.io/mediacapture-screen-share/#dom-mediatracksupportedconstraints-restrictownaudio) says that audio generated by the user of Screen Capture API must be removed from any captured system audio. If the only way to do this is to remove too much audio, that is still allowed. So what exactly is filtered by setting [restrictOwnAudio](https://w3c.github.io/mediacapture-screen-share/#dom-mediatracksupportedconstraints-restrictownaudio) true is implementation specific, as long as the audio from the capturing document is removed.

## User-Facing Problem

The problem to solve is to prevent echos when a captured surface containing system audio is shared in a video conference. If [restrictOwnAudio](https://w3c.github.io/mediacapture-screen-share/#dom-mediatracksupportedconstraints-restrictownaudio) is used when the video conference starts a [Screen Capture](https://w3c.github.io/mediacapture-screen-share/), the audio generated by the video conference is not part of the captured audio, so the participants will not hear echoes of their own voices in the shared audio.

### Goals

- Provide an option for [Screen Capture](https://w3c.github.io/mediacapture-screen-share/) to make sure any captured system audio do not contain audio generated by the page that start the [Screen Capture](https://w3c.github.io/mediacapture-screen-share/).

### Example

[restrictOwnAudio](https://w3c.github.io/mediacapture-screen-share/#dom-mediatracksupportedconstraints-restrictownaudio)  will only have effect if a user chooses to share a window or screen and opt to also share system audio. If a tab is shared, or if the user opts to not share system audio while sharing a window or screen, no system audio is shared and [restrictOwnAudio](https://w3c.github.io/mediacapture-screen-share/#dom-mediatracksupportedconstraints-restrictownaudio)  will have no effect.

Starting a [Screen Capture](https://w3c.github.io/mediacapture-screen-share/) with [restrictOwnAudio](https://w3c.github.io/mediacapture-screen-share/#dom-mediatracksupportedconstraints-restrictownaudio)  set. If the end used chooses to share a window or screen with system audio, the captured audio will not contain audio generated by the page that calls `getDisplayMedia()`

```js
const stream = await navigator.mediaDevices.getDisplayMedia({
  video: true, audio: {restrictOwnAudio: true}});
```

If [restrictOwnAudio](https://w3c.github.io/mediacapture-screen-share/#dom-mediatracksupportedconstraints-restrictownaudio) is set to false or is not set at all, all potentially captured system audio will be shared.

## Alternatives considered
- **Specify that [restrictOwnAudio](https://w3c.github.io/mediacapture-screen-share/#dom-mediatracksupportedconstraints-restrictownaudio) MUST only remove captured system audio from the page that calls getDisplayMedia():** This might be infeasible due to API limitations on different platforms, so the decision is to allow implementations that remove additional audio from the captured system audio if that is needed.

## Accessibility, Privacy, and Security Considerations

[restrictOwnAudio](https://w3c.github.io/mediacapture-screen-share/#dom-mediatracksupportedconstraints-restrictownaudio) reduces the scope of what audio is captured and shared in a [Screen Capture](https://w3c.github.io/mediacapture-screen-share/). So this change does not add any privacy concerns that’s not already handled by [Screen Capture](https://w3c.github.io/mediacapture-screen-share/).

Since [restrictOwnAudio](https://w3c.github.io/mediacapture-screen-share/#dom-mediatracksupportedconstraints-restrictownaudio) might not be implemented on all platforms, a web application can get some limited information about the user’s system by checking for [restrictOwnAudio](https://w3c.github.io/mediacapture-screen-share/#dom-mediatracksupportedconstraints-restrictownaudio) availability. But any information will be very broad.
